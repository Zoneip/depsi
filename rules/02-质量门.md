# 02 · 质量门

每条门都要写清：命令、通过标准、是否改动数据、失败怎么办。**没有执行的门必须标注未执行及原因**。

## G1 · 单元测试（必过）

```bash
cd workspace/depsipy
.venv/bin/python -m pytest tests -q
```

- 通过标准：全绿，0 skipped（环境缺少可选依赖导致的 skip 需在报告中说明）。
- 数据：只写 `tmp_path`，不碰工作区。
- 失败处理：立即修；若为已知语义差异，必须同时更新 `docs/parity.md` 并说明为何不是 bug。

## G2 · 合成数据端到端（必过，M2 起）

```bash
PYTHONPATH=src .venv/bin/python -m depsipy.cli simulate --out /tmp/dp_sim --seed 0
PYTHONPATH=src .venv/bin/python -m depsipy.cli run /tmp/dp_sim/param_file.txt
PYTHONPATH=src .venv/bin/python -m depsipy.cli validate /tmp/dp_sim
```

- 通过标准见 `specs/SPEC-001-*.md` §6（PSC 找回率、速率相关系数、RMS）。
- 数据：只写 `/tmp`。
- 失败处理：定位是选择、估计还是解缠；把失败样本留在 `/tmp` 并在报告中给出路径。

## G3 · 物理一致性不变量（必过，可作单元测试落地）

- 噪声自由数据：解缠后残差 ≈ 0，`ens_coh ≈ 1`，参数精确复原。
- 整数解在 `Qahat` 度量下对 ±1 邻域最优。
- 任意网络：`A·x` 与 `dphase` 的残差在参考点外不随参考点选择改变（只差常数）。
- `sig2_est` 应与注入噪声方差同量级（±3×）。

## G5 · 性能基准（M4 起）

```bash
PYTHONPATH=src .venv/bin/python benchmarks/run_bench.py --scale small
```

- 通过标准：各步骤耗时与峰值内存写入 `benchmarks/out/report.md`；相对上一轮无 ≥2× 回退。
- 数据：`benchmarks/out/`（已 gitignore）。
- 说明：无 MATLAB 环境，**与 MATLAB 的比较只能是复杂度/字节量的估算**，报告中必须如此标注。
